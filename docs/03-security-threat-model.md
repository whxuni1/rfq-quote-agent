# 03 — Security threat model (RFQ Quote Agent)

Status: assessment only. No application code, configuration, or security settings were changed. No customer data was sent to any external service. No exploit was executed.

Inspection date: 19 Nov 2026 (Asia/Shanghai).
Repository state: `main` at `6acddbdf6eda72fc0df583e67bf232c113346a83` (`init: prompt set`, 30 Jun 2026 16:34 CST).
Scope: every file in the working tree. There is no `src/`, `tests/`, `requirements.txt`, `pyproject.toml`, `.gitignore`, CI workflow, environment file, identity provider, or MCP manifest.

## 1. How to read this assessment

| Label | Meaning |
|---|---|
| Verified control gap | The control is absent. Confirmed by reading the repository. Not a demonstrated runtime compromise, because there is no running system. |
| Design defect | The written architecture, if implemented as specified, creates the failure. |
| Hypothetical | Depends on a model obeying injected instructions, or on a deployment choice the spec does not make. |

Nothing below is a verified exploitable vulnerability in a deployed build. The critical items are verified omissions and specified behaviors that would become vulnerabilities on the first pilot that processes a real OEM RFQ.

## 2. System under assessment

Specified pipeline: untrusted PDF + Excel RFQ → ingestion (parser + LLM) → orchestrator LLM plan → engineering / procurement / finance / commercial agents → rule-based human gate → quote draft rendered to Markdown/HTML. Shared state is one mutable `Blackboard` keyed by `rfq_id`. Tools are specified as local pure functions. Production `run_rfq` is specified to call a real LLM client unless a test double is injected.

Trust boundaries that matter:

1. Customer document → parser → prompt → model provider.
2. Model output → Pydantic object → deterministic cost tools and gate rules.
3. Human `ReviewDecision` → field overrides on reports → released `QuoteDraft`.
4. Process memory and `./runs/<rfq_id>/` → whoever can read the host.

## 3. Controls the specification already gets right

These are design intent, not implemented code. Keep them when the tasks are built.

- Money math is assigned to deterministic tools. Finance is specified as zero-LLM (`tasks/13-finance.md`).
- Gate *evaluation* is specified as pure rules, not an LLM (`tasks/17-human-loop.md`, `docs/00-architecture.md` §5).
- Missing reviewer callback fails closed: gate triggered and `reviewer_cb is None` → `blocked` (`tasks/30-eval-harness.md`). Review timeout → `blocked`, not auto-approve (`tasks/17-human-loop.md`).
- Tool layer is forbidden from importing HTTP or provider SDKs (`tasks/20-tool-layer.md`, `AGENTS.md` §2.1).
- `LLMClient` is injectable, so an offline or private endpoint is possible (`docs/01-repo-structure.md`).
- Sub-agents do not call each other. The orchestrator is the only status mover, by convention (`docs/00-architecture.md` §3).
- Override is required to pass a Pydantic type check rather than be applied blindly (`tasks/17-human-loop.md`).
- Eval and fixture generation are specified to run without a network (`tasks/30-eval-harness.md`).

## 4. Findings

### TM-01 — No tenant isolation

- Class: verified control gap and design defect.
- Severity: Critical. Confidence: High.
- Evidence: `Blackboard` is a single in-process object keyed only by `rfq_id` (`docs/00-architecture.md` §3, lines 47–63; `docs/02-shared-schemas.md` lines 249–264). `RFQPackage.customer` is a free string, not a tenant principal (`docs/02-shared-schemas.md` lines 8–20). `run_rfq` takes filesystem paths and an optional caller-supplied `rfq_id` (`tasks/30-eval-harness.md` lines 67–80). Artifacts are specified as `./runs/<rfq_id>/` with no owner, ACL, or namespace.
- Failure: two OEM engagements on one host share one directory and one id space. A caller who can choose `rfq_id`, or who can list `./runs/`, reads another customer's BOM, should-cost, margin, liability position, and review notes. The id is not bound to an authenticated tenant.
- Business impact: cross-customer disclosure of automotive RFQ intellectual property and of this company's pricing position. That is an NDA and procurement-integrity event.
- Remediation: add a required `tenant_id` on every persisted model. Derive storage keys as `tenant_id/rfq_id` inside a rooted directory. Reject `rfq_id` values that are not a UUID generated by the service. Enforce tenant match on every read, resume, and render. One blackboard instance must not be reachable from another request.
- Verification: two fixtures under tenant A and tenant B. Assert B's token listing or opening A's `rfq_id` returns not-found, and that a path under `runs/` for A is not openable by B's resolver.

### TM-02 — No RBAC and no least privilege

- Class: verified control gap.
- Severity: Critical. Confidence: High.
- Evidence: no user, role, scope, or permission type exists in `docs/02-shared-schemas.md`. `ReviewDecision.decided_by` is an unconstrained `str` (lines 231–237). The approver is an injected callback with no authenticator (`tasks/10-orchestrator.md` lines 59–60; `tasks/17-human-loop.md` lines 40–47). Engineering, procurement, finance, and commercial are job stages, not permissions. Wave 1 agents both receive the full `RFQPackage`, including commercial raw text. `skip_agents` is chosen by the orchestrator LLM (`tasks/10-orchestrator.md` lines 29–33).
- Failure: anyone who can call `run_rfq` or `reviewer_cb` can accept a margin-floor breach, a liability cap above the company standard, or a single-source SoC. The name in `decided_by` can be any string. A document-controlled plan can skip engineering or finance. `DATA_MISSING` fires when a report is `None`, but an intentional skip is specified as success for spare-parts work, so a skip is not the same control as a failure.
- Business impact: a quote that commits price, warranty, and liability can be released without a finance or legal approver. Attribution of who approved it is not trustworthy.
- Remediation: introduce a server-side principal (`sub`, `tenant_id`, `roles`). Bind `decided_by` to that principal. Map gate types to roles (`MARGIN_*` → finance approver, `TERM_GAP_*` and warranty → commercial approver, spec and single-source → engineering approver). The requester cannot approve their own packet. `skip_agents` comes from a rule table on `project_type`, never from model output. Field-level prompt views: commercial raw text does not go to the engineering model; should-cost lines do not go to the customer letter.
- Verification: a principal with role `viewer` calling resume is rejected. A `procurement` principal cannot close `MARGIN_FLOOR_BREACH`. A model JSON payload containing `skip_agents: ["finance"]` does not change the agent plan when `project_type` is `NPI+Mass`.

### TM-03 — Prompt injection through uploaded RFQ documents

- Class: design defect. Model compliance is hypothetical until a model is wired. The data flow is verified in the spec.
- Severity: High. Confidence: High on the data flow. Medium on whether a given model follows an injected instruction.
- Evidence: unsanitized document text is specified as model input in ingestion (`tasks/15-ingestion.md` lines 41–47), orchestrator planning (`tasks/10-orchestrator.md` lines 29–33), engineering gap analysis (`tasks/11-engineering.md` lines 27–31), procurement reclassification (`tasks/12-procurement.md` lines 53–56), commercial term extraction (`tasks/14-commercial.md` lines 19–22 and 46–49), and quote-letter polish (`tasks/16-assembler.md` lines 40–44). Gate rules then trust those structured fields (`tasks/17-human-loop.md` lines 18–27). `SINGLE_SOURCE_CRITICAL` matches `material_class ∈ {SOC, DISPLAY, CAMERA}`. Spec-gap severity and ambiguity severity are model-produced. Commercial numbers are model-extracted and only range-checked to `[0, 500]`.
- Failure: a specification section or a BOM cell contains an instruction, or a second conflicting clause. The model reclassifies a SoC as `OTHER`, lowers `gap_severity`, extracts a benign liability cap from the instruction instead of the real clause, or fills `QuoteIntent.skip_agents`. Deterministic should-cost then prices the wrong class. The single-source gate does not fire. The approver sees `ReviewGate.context` values that include customer-controlled strings (`tasks/17-human-loop.md` line 29), which is a social-engineering path even when the gate still fires.
- Business impact: understated cost, a missed single-source or safety-grade risk, or a commercial position the rule library would have rejected. The architecture's claim that "any step that affects a number disables the LLM" (`docs/00-architecture.md` §5) is not true for classification, term extraction, or agent selection.
- Remediation: treat all document text as data. Delimit it and instruct the model that it cannot choose tools, agents, or severities. Freeze `material_class`, `skip_agents`, and gate severity in rule code. Use the model only to propose candidates that a second deterministic checker accepts. For commercial terms, run a rule extractor (numbers, Incoterms, durations) and let the model only attach spans. Show approvers the source span next to the extracted value. Drop model output that mentions instructions, other gate ids, or fields outside the response schema.
- Verification: a fixture PDF whose body says to skip finance, reclassify the SoC, and report liability at 10 percent, while a table states liability cap 150 percent and the BOM part is an SoC. Assert `material_class` stays `SOC`, finance still runs, and the term gap is critical from the table. Assert the approver packet quotes the table span.

### TM-04 — Sensitive data leaves the internal boundary

- Class: verified control gap and design defect.
- Severity: High. Confidence: High.
- Evidence: the customer-facing letter is polished from `pricing_summary`, commercial terms, and the risk register (`tasks/16-assembler.md` lines 40–44). `render_quote` emits the cost sheet, assumptions, exceptions, and the full review trail (`tasks/16-assembler.md` lines 49–53; `docs/02-shared-schemas.md` lines 266–316). `cost_basis` records should-cost versus historical price. Tool logs are specified to record key intermediate values at debug (`tasks/20-tool-layer.md` lines 83–85) with no redaction policy. Architecture §7 says each trace stores an input summary; `AgentTrace` in the schema does not, so implementers are pushed toward logging prompt content (`docs/00-architecture.md` lines 105–106 versus `docs/02-shared-schemas.md` lines 312–316). Runs land on the local filesystem (`tasks/30-eval-harness.md` line 80).
- Failure: a quote HTML or Markdown package sent to the OEM contains internal should-cost, supplier margin, reviewer rationale, and waiver notes. Debug logs and `./runs/` retain the same material for anyone with host or log access. The letter model receives internal risk text and can echo it into `summary`.
- Business impact: loss of pricing power and disclosure of internal risk acceptance. Review notes can be legally sensitive.
- Remediation: split `QuoteDraft` into `internal_pack` and `customer_pack`. The customer pack has price, NRE, validity, and accepted exceptions only. Letter polish receives only the customer pack. Logs get `rfq_id`, agent, step, token counts, and hashes. Prohibit document text, prices, and `decided_by` free text at info and debug. Set a retention period on `runs/` and restrict the directory mode.
- Verification: render the customer pack for case 2 and assert it does not contain `supplier_margin`, `commodity_basis`, `rationale`, or `should-cost`. A log capture test asserts the fixture's distinctive part description never appears.

### TM-05 — Secrets and pricing knowledge have no management model

- Class: verified control gap.
- Severity: Medium. Confidence: High.
- Evidence: the only specified environment variable is `RFQ_AGENT_DATA_DIR` (`tasks/20-tool-layer.md` lines 32–33). `LLMClient.chat` has no credential interface (`docs/01-repo-structure.md` line 43). Commodity prices, processing rates, and standard commercial terms are repository YAML (`tasks/20-tool-layer.md` lines 17–19; `tasks/12-procurement.md` lines 27–30). There is no `.gitignore`, no secret scanner, and no split between test and production credentials. `llm/mock.py` is banned from production only by an import convention (`tasks/30-eval-harness.md` line 92).
- Failure: when a real client is added, the key is likely to land in the environment of the same process, in a task file, or in git. A committed price book is readable by everyone with repo access. A test mock imported by the production entrypoint would silently "succeed" with no provider controls.
- Business impact: provider-key theft, or quotes priced from an unapproved book. Less severe today only because no key exists.
- Remediation: read provider credentials from a secret store at process start. Fail startup if the key is present in argv or in the repo. Decide whether `commodity_prices.yaml` is public fixture data or confidential; if confidential, load it from the secret store and keep a synthetic book in git. Add a production import guard that refuses `llm.mock`.
- Verification: `git grep` plus a secret scanner is clean. A unit test imports the production runner with `RFQ_LLM_MODE=mock` and expects a configuration error. A synthetic key in a fixture file fails CI.

### TM-06 — MCP tool permissions

- Class: verified absence. Residual risk is hypothetical.
- Severity: Low. Confidence: High that no MCP surface exists.
- Evidence: repository search finds no MCP server, client, tool manifest, or permission policy. The tool API is in-process (`tasks/20-tool-layer.md` lines 51–75): `extract_spec(pdf_path)`, `parse_bom(xlsx_path)`, `render_quote(...)`. Those functions have no actor argument.
- Failure: there is no MCP permission bug to exploit today. If these functions are later exposed as MCP tools with the specified signatures, a tool principal could read any path the process can read and return full BOM and quote text. There is no allowlist, no tenant argument, and no side-effect approval hook because the tools are specified as pure.
- Business impact: none in the current tree. High if a future MCP adapter copies the raw-path signatures.
- Remediation: do not expose these tools over MCP in the first release. If a broker is added, replace path arguments with `tenant_id` + `document_id`, enforce the same RBAC as `run_rfq`, and reject any tool that performs network, mail, or ERP actions. There are no legitimate external actions in this product.
- Verification: CI asserts the tree contains no MCP server package and no tool registry. A later adapter test uses a path outside the tenant root and expects denial.

### TM-07 — Unauthorized external actions, and a contradictory LLM default

- Class: verified specification conflict. No live egress was observed.
- Severity: High. Confidence: High.
- Evidence: `AGENTS.md` §2.1 forbids external network APIs and ERP/PLM/supplier connections. `tasks/20-tool-layer.md` line 30 forbids `requests`, `httpx`, `openai`, and `anthropic` in the tool layer. `tasks/30-eval-harness.md` lines 78–79 say the default LLM is a real client in production, and line 94 says eval must not use the network. No egress allowlist, private endpoint, or "offline" production profile is specified. The renderer returns a string and does not send mail.
- Failure: an implementer following task 30 ships a default that transmits the RFQ to a model provider. An implementer following `AGENTS.md` does not. The dangerous interpretation is the code default. No other external action (email, ERP write, supplier inquiry) is designed; that part of the threat is contained by omission.
- Business impact: unapproved transfer of OEM confidential data. Contract and privacy exposure starts at the first production call.
- Remediation: make `llm_mode` explicit and required: `off`, `local`, or `approved_endpoint`. Default `off` for any path that can see a real file. `off` uses templates for letter text and rules for extraction. Startup refuses to run if an HTTP client is configured and `llm_mode` is `off`. Keep the tool-layer import ban and enforce it with a lint rule.
- Verification: a test monkeypatches socket connect and runs `run_rfq` with the default config on a fixture. The test expects zero connect attempts. A separate test opts in to a local fake endpoint and expects only that host.

### TM-08 — Approval bypass

- Class: design defect. This is the control that releases a commercial commitment.
- Severity: Critical. Confidence: High.
- Evidence:
  - Second trigger of the same `gate_id` auto-passes (`tasks/10-orchestrator.md` line 50; `tasks/17-human-loop.md` lines 49–51). The acceptance test requires a still-true margin gate to pass on the second evaluation (`tasks/17-human-loop.md` line 67).
  - `gate_id` derivation is undefined (`docs/02-shared-schemas.md` lines 214–222). A random id never matches, so the safety latch never engages. An id based only on gate type permanently disarms that control after one decision.
  - `GateDecision.override` is `dict[str, Any]` (lines 239–243) applied onto reports (`tasks/10-orchestrator.md` lines 47–50). The type check has no field allowlist (`tasks/17-human-loop.md` lines 73–76). Specified examples include changing margin and changing a BOM line.
  - `Blackboard` is the only mutable model (`docs/02-shared-schemas.md` line 250). Status is a plain string. Nothing in the schema stops a holder from setting `assembling`.
- Failure: an approver, or a caller forging `ReviewDecision`, selects an option that does not remove the condition. The re-check sees the same gate and auto-clears it. Alternatively the override sets `margin_floor_breached` to false, changes `supplier_landscape`, or rewrites a BOM line, and the next gate check is clean. A still-critical liability or margin position is then assembled into a quote.
- Business impact: the human gate, which is the product's main safety control, can be satisfied without the underlying risk changing and without a second person.
- Remediation: delete auto-pass. A gate clears only when the predicate is false, or when a waiver record exists. A waiver names gate type, tenant, rfq, principal, role, expiry, and a hash of the values being waived. It cannot waive a different amount than the one shown. Overrides are a typed allowlist per gate (`proposed_margin_pct` for margin, a specific BOM line substitution for spec gap). Overrides cannot set `margin_floor_breached`, `status`, `supplier_landscape`, or `material_class`. Critical waivers require two roles. The assembler recomputes `GateEvaluator.evaluate` and refuses `done` if a critical predicate is still true without a matching unexpired waiver.
- Verification: force `proposed_margin_pct` below the floor, submit a decision that does not raise it, and assert the second check still returns `awaiting_review`. Submit an override containing `margin_floor_breached: false` and assert validation rejects it. Assert `assemble` throws if status was set to `assembling` while the predicate remains true.

### TM-09 — Audit log integrity

- Class: verified control gap and design defect.
- Severity: High. Confidence: High.
- Evidence: `decision_log` and `trace` live on the mutable blackboard (`docs/02-shared-schemas.md` lines 261–263). `review_trail` is a copy of that list (`tasks/16-assembler.md` line 38). `AgentTrace` stores an output hash, not a hash chain (lines 312–316). `decided_at` is supplied by the caller (line 236). `datetime.now()` is the specified clock (`tasks/20-tool-layer.md` line 81). The run directory is an ordinary folder. No signature, append-only store, or tamper event is specified.
- Failure: the process, or anyone who can edit `./runs/`, can drop a decision, change `decided_by`, or backdate `decided_at`. After the fact, a quote cannot be shown to be the one that was approved. A crash before assemble loses the in-memory log.
- Business impact: the company cannot defend a pricing or liability decision in a customer dispute or an internal investigation.
- Remediation: append-only audit store, separate from the blackboard. Each event stores `prev_hash`, canonical payload hash, server timestamp, tenant, actor, and rfq id. `QuoteDraft` carries the terminal hash. Verify the chain at assemble time. Callers cannot set `decided_at`.
- Verification: flip one byte of an intermediate event and assert verification fails. Replay a decision with a client-supplied timestamp and assert the stored time is the server clock. Kill the process after a decision and assert the event is still readable.

### TM-10 — Model-provider retention and private deployment

- Class: verified control gap. Provider behavior is not verifiable because no provider is configured.
- Severity: High. Confidence: High on the missing control.
- Evidence: no provider name, region, retention flag, zero-retention clause, private-link setting, or customer-managed key appears in any file. The production default in task 30 is "a real client". The offline mock is test-only. Local strengths that do exist: PDF and Excel parsing, should-cost, rollup, gates, and rendering are specified as local functions; the client is an interface.
- Failure: the first production implementation sends full specification sections, BOM rows, commercial clauses, and possibly internal risk text to a multi-tenant provider that trains on or retains prompts. There is no documented air-gapped or VPC mode to offer a customer.
- Business impact: OEM contracts for cockpit and ADAS hardware commonly prohibit this. A retention incident is a customer-trust and bid-eligibility failure.
- Remediation: publish three profiles and refuse to start unless one is selected.
  - `airgap`: no model egress. Rules and templates only, or a model on localhost with outbound network denied.
  - `private_vpc`: one approved endpoint, private DNS, region pinned, contractually zero retention and no training. Log the endpoint id in the audit event, not the prompt.
  - `public_provider`: disabled for any input classified as customer RFQ.
  Record the profile on the quote. Add a local adapter behind `LLMClient` so private deployment is a configuration change.
- Verification: configuration tests for all three profiles. The airgap test is the socket test from TM-07. A document test lists the approved endpoint and the retention commitment; CI fails if `llm_mode` defaults to a public host.

### TM-11 — Untrusted files: path write, HTML injection, parser limits

- Class: design defect. No parser was fuzzed.
- Severity: High. Confidence: High on path and render design. Medium on parser memory exhaustion, which is hypothetical until code exists.
- Evidence: `extract_spec` and `parse_bom` take raw paths (`tasks/20-tool-layer.md` lines 53–57). Run output is `./runs/<rfq_id>/` (`tasks/30-eval-harness.md` line 80) and `rfq_id` is an unsanitized `str`. HTML is built with f-strings from quote fields that contain BOM descriptions and review notes (`tasks/16-assembler.md` lines 49–53). No size, timeout, or sandbox is specified for pdfplumber or openpyxl. Macros are not in scope; openpyxl does not execute them, and that should stay true.
- Failure: `rfq_id` `../` or an absolute segment writes the quote outside the run root. A part description containing a script tag becomes stored HTML when a reviewer opens the quote in a browser. A hostile spreadsheet or PDF can exhaust memory in-process. No malware scan is specified.
- Business impact: local file overwrite on the quote server, script execution in a reviewer's browser, or a availability break of the quoting pipeline.
- Remediation: generate `rfq_id` internally. Resolve artifact paths with a root check (`relative_to` the run root and reject escapes). Escape HTML and do not interpolate raw text into tags. Cap upload size, page count, sheet count, and parse time. Parse outside the request worker if a sandbox is available. Do not evaluate spreadsheet formulas.
- Verification: `rfq_id` values `../etc`, `a/b`, and an absolute path do not create files outside the root. A part description `<script>` is escaped in the HTML fixture. A workbook over the sheet limit returns `IngestionError` without allocating unbounded strings.

### TM-12 — Unsigned pricing configuration

- Class: design defect.
- Severity: Medium. Confidence: High.
- Evidence: YAML price and terms files load at import through `lru_cache`, with `RFQ_AGENT_DATA_DIR` overriding the directory (`tasks/20-tool-layer.md` lines 32–33). Procurement also allows a CSV price override (`tasks/12-procurement.md` line 77). Load-time Pydantic checks shape, not authenticity.
- Failure: a process environment or a writable data directory changes every should-cost and the company standard terms. A long-lived process keeps the first loaded book after a legitimate update (`lru_cache`).
- Business impact: systematic mispricing. Hard to detect quote by quote.
- Remediation: sign the price book and standard terms. Pin the digest on the quote and in the audit event. Ignore unsigned overrides unless the principal has role `pricing_admin`. Reload on an explicit version bump rather than a process-lifetime cache.
- Verification: a flipped byte in `commodity_prices.yaml` fails startup. A quote record contains the book digest. Two calls with different digests do not silently share one cache entry.

### TM-13 — Shared mutable blackboard under concurrent agents

- Class: design defect.
- Severity: Medium. Confidence: Medium. asyncio interleaving is likely. It was not executed.
- Evidence: wave 1 and wave 2 use `asyncio.gather` on one blackboard (`docs/00-architecture.md` lines 40–43 and 108–110; `tasks/10-orchestrator.md` lines 35–40). Both agents append `trace` and may touch shared lists. The object is mutable by design.
- Failure: cooperative tasks interleave on `trace`, `decision_log`, or status and drop an audit event or overwrite a report reference. That is corruption and an audit gap, not by itself cross-tenant access.
- Business impact: missing engineering or procurement output, or a trace that does not match the quote.
- Remediation: give each agent an immutable input view and a private result object. Only the orchestrator merges results onto the blackboard, on a single task, after `gather` returns. Append audit events through the TM-09 API, not a shared list.
- Verification: a test where both wave-1 agents await and then append 100 trace events yields exactly 200 events in a defined order.

### TM-14 — Supply chain and CI are specified but absent

- Class: verified control gap.
- Severity: Medium. Confidence: High.
- Evidence: `docs/01-repo-structure.md` lines 19–20 and 88 require `requirements.txt`, `pyproject.toml`, and `.github/workflows/ci.yml`. None of those files exist. The specified CI is lint and tests only: no lockfile, no dependency review, no secret scan, no SAST.
- Failure: the first implementation will add `pdfplumber`, `openpyxl`, and an LLM SDK without a pin or a vulnerability gate. A malicious or typo-squatted dependency runs in the same process as customer RFQs.
- Business impact: remote code execution in the quoting environment, or a quiet dependency that adds network egress and defeats TM-07.
- Remediation: add a lockfile and CI before task 15 merges: ruff, mypy, pytest, `pip-audit` or equivalent, secret scanning, and an import lint banning HTTP clients outside `llm/`. Review new dependencies in the PR.
- Verification: CI fails on a known-vulnerable pin and on `import httpx` under `src/rfq_agent/tools/`.

## 5. STRIDE snapshot

| Threat | Where it shows up |
|---|---|
| Spoofing | `decided_by`, caller-supplied `rfq_id`, no principal |
| Tampering | open `override`, mutable blackboard, unsigned price book, path write |
| Repudiation | client clock, unsigned decision log |
| Information disclosure | no tenant boundary, LLM egress, logs, customer render of internal fields |
| Denial of service | unbounded parse, in-process parser, gate re-entry |
| Elevation of privilege | `skip_agents`, material reclassification, auto-pass, role-less approver |

## 6. Prioritized remediation plan

Do not ingest a real customer RFQ until P0 is accepted and the tests in §7 exist. Task files `tasks/15` through `tasks/30` should not be implemented as written; they encode TM-03, TM-07, TM-08, and TM-11. Amend the tasks first. This assessment does not make those amendments.

### P0 — design blockers, before the first feature PR

1. Resolve the egress contradiction. Required `llm_mode` of `off`, `local`, or `approved_endpoint`. Default `off`. Public providers are out of policy for RFQ content (TM-07, TM-10).
2. Add `tenant_id` and server-generated `rfq_id`. Root the run directory (TM-01, TM-11).
3. Add a principal and role checks. Bind `decided_by`. Rule-based `skip_agents` (TM-02).
4. Remove second-trigger auto-pass. Typed waiver plus per-gate override allowlist. Assembler re-evaluates predicates (TM-08).
5. Freeze `material_class` and gate severity in rules. Document text is untrusted data. Commercial numbers come from a rule extractor with source spans (TM-03).
6. Split customer pack from internal pack before any renderer or letter model sees the draft (TM-04).

### P1 — build with the first implementation tasks

7. Append-only hash-chained audit log and server timestamps (TM-09).
8. Log redaction and a ban on prompt bodies in traces (TM-04).
9. Signed price book and standard terms. Secret-store credentials. Production refuses the mock client (TM-05, TM-12).
10. HTML escaping, upload limits, parse timeout (TM-11).
11. Single-writer blackboard merge (TM-13).
12. Lockfile, dependency audit, secret scan, HTTP-import lint. No MCP adapter (TM-06, TM-14).

### P2 — before a multi-tenant or production pilot

13. Per-tenant storage ACL and a documented airgap and private-VPC runbook, including the retention commitment of the approved endpoint (TM-01, TM-10).
14. Two-person rule for critical waivers (margin floor, liability cap, single-source SoC).
15. Eval fixtures for injection, cross-tenant access, override rejection, path escape, and zero egress. These join `tests/eval/` as release gates, not as samples to send to a provider.

## 7. Release-gate tests

| Test | Pass condition |
|---|---|
| `test_tenant_isolation` | Tenant B cannot read tenant A's run, blackboard, or quote |
| `test_rbac_resume` | Wrong role cannot close a gate; `decided_by` matches the authenticated subject |
| `test_skip_agents_not_from_model` | Model JSON cannot drop finance on an NPI job |
| `test_injection_fixture_soc_and_liability` | SoC class, finance execution, and critical liability gap survive hostile document text |
