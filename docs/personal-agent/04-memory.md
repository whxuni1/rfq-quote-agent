# 04 — 个人记忆

对标 Muse "记住只提过一次的细节并主动运用"，同时保证**用户可见、可改、可删**。

## 1. 记忆类型

| 类型 | 内容 | 例子 | 版本 |
|---|---|---|---|
| `fact` | 关于用户/其关系人的稳定事实 | "对花生过敏"、"张三是同事，邮箱…" | MVP |
| `preference` | 偏好与风格 | "邮件偏正式"、"订酒店优先靠窗" | MVP |
| `episode` | 事件/交互摘要 | "9/20 比较了三款 SUV，倾向 A" | v0.2 |
| `procedure` | 用户教过的做法 | "报销先填 A 表再抄送 B" | v0.3 |

## 2. 写入

1. 每轮对话/目标结束后，Memory Extractor（LLM, `model_role=memory`）从**用户本人发言**中抽取候选记忆，输出 `MemoryCandidate`（含原文引用片段）。
2. 去重合并：与已有记忆按 `subject+predicate` 键及语义相似度比对 → new / update / conflict。
3. 冲突（如新旧偏好矛盾）→ 保留新值，旧值标记 `superseded`，并在下次相关使用时提示。
4. **来源规则**：来自 untrusted 工具结果（网页、邮件正文）的候选记忆**不自动入库**，进入"待确认记忆"列表。
5. 敏感类别（健康、财务、证件、宗教、政治等）自动打 `sensitive` 标签 → Sentinel 数据流规则生效。
6. 用户可以说"记住…/忘掉…"显式操作，优先级最高。

## 3. 召回

- MVP：关键词 + subject 精确匹配 + 最近使用；v0.2 加 sqlite-vec 向量召回 + LLM 重排。
- 每次注入上下文的记忆 ≤ N 条（默认 12），带 `memory_id`。
- 回复中使用了记忆时，**必须可溯源**：UI 展示"用到的记忆"，用户可点开编辑/删除。

## 4. 遗忘与治理

- 删除为硬删除（含向量索引与派生摘要）；审计日志只记"某 id 被删除"，不保留内容。
- `episode` 类按时间衰减，超过保留期（默认 180 天）且未被引用则归档/删除。
- 全量导出：JSON（schema 见 `02-schemas.md`）。
